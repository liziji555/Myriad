# 苦乐

> 原名 SuperAgent。命令行叫 `sa`，仓库、数据目录和导出的文件名里还是 `superagent`，没有跟着改。

Rust 多 Bot Agent Harness：房间里的 AI 团队。一个可执行文件，自带内核、本机服务和界面。

## 现在能做什么（M7b）

- 任务：Bot 把要花些功夫的事开成任务，在独立的目录里做，做完交给你验收；验收通过，改动才回到你的工作目录
- 任务里可以派子代理去查资料（只读），可以把任务分支推到远端、在 GitHub 上开 PR（每次都要你批准）
- 一个房间里放几个 Bot，各有分工：`@名字` 点名谁就谁答；不点名时按分工挑一个
- Bot 之间可以互相点名交接、复核，有次数上限，不会没完没了地互相回复
- 在房间里和 Bot 对话：回复边写边显示，可以中途停止
- Bot 能用只读工具查资料：读文件、列目录、按名字找文件、按内容搜索、抓公开网页
- Bot 能动手：写文件、改文件、执行命令（Windows 用 PowerShell，其他系统用 bash）、列待办清单
- 有风险的操作先问你：审批卡上可以选「允许一次」「总是允许」「拒绝」
- 「停止」会连同命令启动的子进程一起结束
- 对话太长时自动把前面的部分压缩成摘要，之后接着聊
- 会话记录落盘，重启后历史还在，Bot 记得前面聊过什么
- `sa serve`：本机服务 + 界面（顶上的现场栏写着每个 Bot 在做什么，中间一条主线，房间列表和面板按需呼出）
- `sa chat`：在终端里对话
- `sa task`：在终端里看任务、开任务、验收
- 花费有上限：每天的上限到了就暂停调用模型，每个任务也有上限；界面右侧「用量」页和 `sa usage` 看花了多少
- 看门狗：跑太久、没动静、花得特别多的任务会被自动停下并提醒你；Bot 转圈说同一句话也会被停下
- 定时任务：到点让一个 Bot 在房间里做一件事，没什么可说时它不出声；界面右侧「定时」页和 `sa routine` 管理
- 命令面板：`Ctrl K`（Mac 上 `⌘ K`）搜房间、Bot、任务和动作，回车直达
- 任务图：界面右侧「活动」页里一个任务一行，画出它的每次运行和现在的状态；刚发生的事有一道光飞到节点上
- GitHub 事件：把仓库连到房间，新的 issue、评论、评审和没通过的 CI 进房间，由 Bot 来看；同一次投递只收一次
- Telegram：把聊天连到房间，在 Telegram 里对机器人说的话进房间，Bot 的回复送回那个聊天
- `sa doctor`：检查数据目录、配置、模型密钥、git、GitHub 令牌、数据库、端口和前端页面

- 技能：把做事的套路写成文件放进数据目录，Bot 碰到对得上的事会先读它再照着做
- MCP：接本机启动的外部 MCP 服务，它们的工具加给每个 Bot，每次调用都要你批准
- 突然断电、进程被杀之后再启动：消息一条不丢；还没人接的话接着回应，写到一半的回复标成「中断」
- 审计日志：谁批准了什么、Bot 执行了什么命令、任务走到了哪一步，都留底；界面右侧「审计」页和 `sa audit` 查
- Bot 模板：把一个房间的团队导出成一个文件，换一台机器或者另开一个房间时导入
- 回复下面的每一步操作可以展开，看它拿到了什么结果
- 界面记得你的摆法：面板开没开、多宽，用浅色还是深色；每个房间里写了一半的话也留着

文档：[安装](docs/安装.md)、[使用](docs/使用.md)、[用六个信号检验](docs/验收.md)、[界面验收 20 条](docs/界面验收.md)。

## 运行

需要 Rust（版本见 `rust-toolchain.toml`）、Node 24 和 pnpm。

```sh
pnpm --dir web install
pnpm --dir web build     # 先构建前端，它会被编进可执行文件
cargo run -p sa-cli -- serve --mock
```

启动后终端会打印一个带令牌的链接，用它打开页面。服务只监听 `127.0.0.1`。

`--mock` 用的是不联网的假模型，不需要密钥，回复按固定规则生成，用来先把流程走一遍。
假模型看消息里反引号前面的动词决定调哪个工具：

| 发这样的消息 | 假模型会做什么 |
|------|------|
| 读一下 `` `README.md` `` | 读文件 |
| 写入 `` `笔记.md` ``：第一行 | 写文件（工作目录里面不用批准） |
| 修改 `` `笔记.md` ``：第一行 => 改过了 | 把文件里的「第一行」换成「改过了」 |
| 运行 `` `git status` `` | 执行命令（会弹审批卡） |
| @Coder 转给 `` `Reviewer` ``：帮我看看 | Coder 点名 Reviewer，Reviewer 接着回答 |
| @Coder 谢谢，不用回了 | 被点到的 Bot 选择不说话 |
| 任务：写入 `` `笔记.md` ``：第一版 | 开一个任务；任务里照冒号后面的写法动一次手，然后交结果等你验收 |
| 任务：这里会卡住 / 任务：这个要问 | 任务报告「卡住了」/ 问你一个问题 |
| 任务：让子代理读一下 `` `README.md` `` | 任务里派一个子代理去读，把它的回答当结果交上来 |
| 任务：写入 `` `笔记.md` ``：第一版，然后开 PR | 任务里写完文件，推送分支、开 PR（各弹一张审批卡；要在 git 仓库里，开 PR 还要令牌） |

房间里有几个 Bot、又没有点名时，假模型按消息里出现的 Bot 名字挑人，都没出现就交给入口 Bot。

### 接上真实模型

默认配置用 DeepSeek。把 API Key 放进环境变量 `DEEPSEEK_API_KEY`，去掉 `--mock` 重新启动：

```powershell
# Windows PowerShell（只对当前窗口有效）
$env:DEEPSEEK_API_KEY = "sk-..."
sa serve
```

```sh
# macOS / Linux
export DEEPSEEK_API_KEY=sk-...
sa serve
```

也可以用别的 OpenAI 兼容服务。以 OpenCode Go 为例，在数据目录的 `config.toml` 里加一段，
再把 `[tiers]` 里三个档位的 `provider` 和 `model` 改过去，密钥放进 `OPENCODE_API_KEY`：

```toml
[providers.opencode-go]
kind = "openai_compat"
base_url = "https://opencode.ai/inference/go/v1"
api_key_env = "OPENCODE_API_KEY"
session_header = "x-opencode-session"   # 这个网关要求每个会话带一个固定的请求头

[tiers]
cheap = { provider = "opencode-go", model = "deepseek-v4.1-flash", thinking = false }
mid = { provider = "opencode-go", model = "deepseek-v4.1-flash" }
strong = { provider = "opencode-go", model = "deepseek-v4.1-flash" }
```

密钥只从环境变量读，不会写进配置文件或数据库。换模型、换服务地址改数据目录里的 `config.toml`，
改完用 `sa doctor` 检查。接上真实模型之前，先按下面「花了多少、什么时候停」把 `[prices]` 改成你用的服务的价格。

### Bot 能看到什么

Bot 的文件类工具只能读「工作目录」里面的内容，默认是启动命令时所在的目录，用 `--workdir <目录>` 指定别的。
数据目录（里面有访问令牌和数据库）即使在工作目录里也读不到。抓网页只能访问公网地址，并且不走系统代理（走代理就没法保证连的不是内网）。

### Bot 能改什么、什么时候问你

| 操作 | 怎么处理 |
|------|------|
| 读文件、搜索、抓网页、待办清单 | 直接执行 |
| 在工作目录里面写文件、改文件 | 直接执行 |
| 写 `.git` 里面的文件（它的配置能让 git 执行命令） | 弹审批卡 |
| 写工作目录之外的文件 | 弹审批卡 |
| 执行命令 | 弹审批卡 |
| 写数据目录 | 一律拒绝，不问 |

审批卡在界面的时间线里；`sa chat` 里是一行提示，输入 `y`（允许一次）、`a`（总是允许）或 `n`（拒绝）。
10 分钟没处理按拒绝算；服务重启时还在等的卡片作废。

「总是允许」只在这个房间里有效，并且只对一模一样的命令、同一个文件有效；它不是通配规则。
已经保存的许可可以通过接口查看和撤销：`GET /api/rooms/{房间}/rules`、`DELETE /api/rules/{id}`。

这个版本没有系统级沙箱：命令一旦批准，就以你的身份运行，能做你能做的任何事。批准之前请看清楚命令。

命令默认最多跑 120 秒（Bot 可以要求最多 600 秒），超时或点「停止」会结束整棵进程树。
工具返回的内容太长时，交给模型的是截短的版本，完整内容存在数据目录的 `spill/` 里。

### 多个 Bot

在界面右侧的「成员」面板（或者用 `sa bot`、`sa room` 命令）新建 Bot、写它的分工、拉进房间。一个房间最多 6 个 Bot。

**谁来接话**

1. 消息里 `@名字` 点了谁，就是谁。输入 `@` 会弹出房间里的 Bot 列表。
2. 没有点名、房间里只有一个 Bot：就是它。
3. 没有点名、房间里有几个 Bot：先让便宜档（`cheap`）的模型看每个 Bot 的分工（前 300 字）和最近几条对话，挑一个；
   它拿不准（把握低于 0.55）或者答得不合格式，换强档（`strong`）再挑一次；还是不行，交给入口 Bot。

所以分工的开头要写清楚这个 Bot 负责什么（别的 Bot 看到的是第一行）。挑人这一步只做分类，不回答问题，也不用工具。

**Bot 找 Bot**

Bot 用 `ask_bot` 工具点名另一个 Bot。话会作为一条消息出现在房间里，对方随后回答；发起的 Bot 不等回答，说完自己的就结束。
界面主线左边会有一根线把这句话连到对方的回复，对方还在做时线上有光在流动。
Bot 在回复里直接写 `@名字` 不会叫到任何人。被叫到但没什么要补充的 Bot 会回 `(pass)`，房间里不留下它的消息。

为了不让 Bot 之间没完没了，人每说一句话：

几个 Bot 同时在说时，这些上限是它们一起算的。

| 上限 | 数值 | 超过时 |
|------|------|------|
| Bot 发言次数 | 6 | `ask_bot` 被拒绝，Bot 被告知把结论直接告诉你 |
| 连续转手 | 3 手 | 同上 |
| 同一对 Bot 互相找 | 2 次 | 同上（两个 Bot 来回客套时第 3 次被掐断） |
| 和最近 6 条 Bot 消息几乎一样的话 | — | 同上 |

**几个 Bot 同时说**

- 一句话里点了几个 Bot，它们一起开始；Bot 用 `ask_bot` 找人，对方马上开始，找人的那个接着做自己的事。
- 一个房间同时最多 3 个 Bot 在说（`config.toml` 里 `[rooms]` 的 `max_parallel_bots`），多的排队，输入框上方显示「接下来：…」，执行卡片上写「排队中」。终端里的 `sa chat` 一次只显示得下一条回复，所以那里固定一个一个说。
- 同时在说的 Bot 只看得到彼此已经写完的话。各自的审批单独等，一个等批准时别的照常做。
- 读文件、搜索不受限；改文件、执行命令在同一个房间里一个一个来，免得同时改同一个文件。要真并行改代码，开任务（每个任务有自己的目录）。

**讨论方式**

面板「成员」页最上面选这个房间里没点名的话怎么接（用 `@` 点了名的总是只给被点到的）：

| 方式 | 没点名时 |
|------|------|
| 普通（默认） | 按分工挑一个 Bot 接，挑不出来交给入口 Bot |
| 并行回复 | 每个 Bot 各答一份，同时开始（受同时最多几个的限制） |
| 轮流讨论 | 按进房间的先后一个接一个说，转 1 到 3 圈（默认 2 圈）；后说的看得到先说的 |
| 独立评议 | 每个 Bot 各答一份，这一轮互相看不到对方的答案；你下一句话之后才看得到 |
| 主 Agent 派活 | 入口 Bot 当主 Agent：没点名的话交给它，它只看不动手，用 `ask_bot` 把活派给成员；派出去的（包括成员又转出去的）都做完后自动交回给它，由它决定接着派还是向你汇报 |

**插话和停止**

- Bot 在说时按回车，这句话进**待发队列**：输入框上方列着，可以改字、往前往后挪、取消；房间里正在说的 Bot 都说完了，排在最前面的一句才发出去，一句一句来。队列存在库里，关掉重开还在。发出去的就不在队列里了，改不了也取消不了。
- 想现在就让正在说的 Bot 看到，点「插话」：不会打断谁，没点名的话所有正在说的 Bot 都会在下一步看到，点了名的只给被点到的（它没在说就让它开始）。
- 执行卡片上的「停止」：只停那一个 Bot（正在说的这一轮和排着的队），别的照常。
- 输入框旁的「停止」：整个房间正在说的都停下，排着队的 Bot 也不再说。待发队列不清掉：停下之后接着发下一句，不想发的在队列里取消。

接口：`GET/POST /api/rooms/{房间}/queue`（请求体 `{"content": "…"}`）、`PATCH /api/queue/{id}`（`{"content": "…"}` 改字，`{"offset": -1}` 或 `1` 挪一位）、`DELETE /api/queue/{id}`。队列变了会发 `queue.updated` 事件。

每个 Bot 在每个房间里有自己的会话记录。它没参与的对话，在它下一次被叫到时会以「【名字】内容」的形式补给它。

**模板：把团队存成文件**

在「成员」面板最下面点「导出这个房间的团队」，或者：

```sh
sa bot export --room <房间> -o team.toml     # 一个房间的团队：成员、谁是入口、房间叫什么
sa bot export Coder Reviewer -o bots.toml    # 只要几个 Bot；一个都不写就是全部
sa bot import team.toml
```

文件是这样的，可以手写，也可以改了再导入：

```toml
version = 1

[[bots]]
name = "Coder"
tier = "strong"          # cheap、mid、strong
persona = "写代码。改完跑测试。"
enabled = true

[room]                   # 可以没有；有的话导入时新建这个房间
name = "修 bug"
host = "Coder"           # 入口 Bot；不写就是第一个成员
members = ["Coder"]
```

- 已经有同名的 Bot（不分大小写）默认跳过，不会改它；模板带了房间时它照样被拉进新房间。
- 想让已有的同名 Bot 也照模板改（档位、分工、是否启用），要明说：`sa bot import team.toml --update`，界面上是导入按钮下面的那个勾。
  全新的数据目录里自带一个「助手」，换机器时原来那个写好了分工的「助手」就靠这个搬过来。
- 模板有一处不对（版本、重名、成员对不上、名字不合规矩），什么都不建。
- 里面只有名字、档位、分工、是否启用和房间的成员，没有密钥、聊天记录、任务和技能。
- 成员在房间里的先后不保证和文件里一样。

### 任务

对话适合问答和小改动；要花些功夫的事（修 bug、加功能、整理一批文件）Bot 会用 `create_task` 开成任务。
你也可以自己开：界面右侧「任务」页的「新建任务」，或者 `sa task add`。

**任务在哪里做**

每个任务有自己的工作会话和独立目录（在数据目录的 `work/` 下面），用强档（`strong`）模型：

- 工作目录是有提交的 git 仓库：给任务开一个 worktree 和一条分支 `sa/task-…`，从当前的 HEAD 开始。
- 不是 git 仓库：把工作目录复制一份（不带 `.git`；超过 5 万个文件或 200 MB 时任务会卡住并告诉你原因）。

任务目录里写文件不用问；执行命令照样弹审批卡，卡片挂在时间线上那条「运行过程」里。需要装了 git。
任务里点的「总是允许」只对这个任务有效，不会让对话里的同一条命令免问（两边不在同一个目录里跑），反过来也一样。

任务里的命令的审批卡上多一个「这个任务里的命令都允许」（`sa task` 里是 `t`）：选了之后，这个任务再执行命令都不问，打回重做的那几次也一样。它只管这一个任务、只管执行命令：

- 对话里的命令、别的任务的命令照样问；`git_push`、`open_pr`、MCP 工具、往任务目录外面写文件照样问。
- 命令里出现 `git … push` 或 `gh` 的照样问。这只是看命令里的词，换个写法（比如写进脚本再执行）就躲得过去，是多一道提醒，不是保证。
- 命令不在沙箱里跑，能做你这个系统用户能做的任何事。选它等于信任这个任务接下来的每一条命令，执行过什么事后在「审计」页查。
- 撤销：`GET /api/rooms/{房间}/rules` 里 `tool` 是 `shell*@任务` 的那一条，`DELETE /api/rules/{id}`。
任务只能读写自己的目录；数据目录里别的东西（令牌、数据库、别的任务）它碰不到。

任务属于它开出来时的那个工作目录：换一个 `--workdir` 启动服务，之前的任务不会在新目录里接着做，也不能往新目录里验收。
同时最多跑 3 个任务，多的排队。每个房间最多 10 个没做完的任务。

**任务的状态**

| 状态 | 含义 | 你能做什么 |
|------|------|------|
| 草稿 | 还没有负责人 | 指定负责的 Bot 后开工 |
| 等着开工 / 正在做 | 排队中 / 在跑 | 带一句话给它（下一步就能看到）、停止 |
| 等你验收 | 做完了，交了结果 | 验收通过，或者写明意见打回重做 |
| 等你回答 | 缺一个只有你能回答的问题 | 回答并继续 |
| 卡住了 | 出错、被停下、命令没被批准 | 补充说明后继续，可以换负责人 |
| 完成 / 不需要做 / 已取消 | 结束了 | — |

任务结束一轮时用 `report` 交结果，时间线上出现一张交付卡：结果说明、改了哪些文件。

**验收**

- 验收通过：git 仓库里是把任务分支合并进你当前所在的分支（任务开了 PR 的除外，见下面）；复制出来的目录是把改动当补丁打回工作目录。然后任务目录删掉（分支留着）。
- git 仓库里，被 `.gitignore` 忽略的文件不算任务的改动，不会带回来（和平常用 git 一样）；复制出来的目录没有这个限制。
- 你自己正合并到一半时不能验收，先把那次合并处理完。
- 改动带不回去（开工之后你也改了同样的地方）：验收失败并说明原因，任务留在「等你验收」，两边的文件都不动。
- 打回：带着你的意见重新排队，接着同一个工作会话做。
- 取消：任务目录删掉，改动不保留。

**子代理**

任务里的 Bot 可以用 `agent` 派一个子代理去查一件事（比如「这个函数在哪些地方被调用」），只拿回结论，翻找的过程不占它自己的上下文。
子代理用中档（`mid`）模型，只有只读工具，不能改文件、不能执行命令、不能再往下派，看不到任务之前的对话。时间线上只显示「子代理：……」这一步。

**推送和开 PR**

工作目录是 git 仓库时，任务里的 Bot 多两个工具，只在任务要求时才用：

- `git_push`：把任务分支推到 `origin`。`origin` 配了几个推送地址就会推到几个地方，审批卡上全部列出。用的是你这个仓库自己的远端和凭据；要输密码时不会等，直接算失败。
- 任务有自己的分支，推的就是它。Bot 在任务目录里另建了分支、切到了别的分支上时，`git_push` 不推送并说明怎么回到任务分支，不会把没更新的任务分支报成推好了。
- `open_pr`：在 GitHub 上给任务分支开 PR。要先推送；一个任务只开一个 PR，再调一次只会把原来的地址报回来。

这两件事发生在你的电脑之外，所以**每次都弹审批卡**，卡上写着推什么、推到哪、PR 的标题和要合进哪个分支；点「总是允许」也只管这一次。

开 PR 需要一个 GitHub 令牌（对仓库有 Pull requests 的写权限），放在环境变量 `GITHUB_TOKEN` 里再启动服务。配置在 `config.toml`：

```toml
[github]
api_base = "https://api.github.com"   # GitHub Enterprise 是 https://主机/api/v3
token_env = "GITHUB_TOKEN"
# repo = "owner/name"                 # 不写就从 origin 的地址里认
```

没有令牌时别的都不受影响，只是 Bot 开不了 PR（它会告诉你，分支推上去之后你也可以自己开）。

开了 PR 的任务，验收通过**不会**再把分支合进本地：改动由你在 GitHub 上合并，任务目录照样删掉，分支留着。
开了 PR 之后任务又有改动还没推送时不能验收（那些改动不在 PR 里）：打回让它再推送一次。

服务重启时还在跑的任务会被标成「中断」，再启动时接着做。

接口：`GET/POST /api/rooms/{房间}/tasks`、`GET /api/tasks/{id}`、`POST /api/tasks/{id}/{resume|accept|reject|stop|cancel}`（请求体 `{"note": "…", "owner_bot_id": "…"}`，都可以不带）。

### 花了多少、什么时候停

每次调用模型之后，按 `config.toml` 里 `[prices]` 的价格把这次的 token 折成钱记下来。这是估算：
实际扣多少以模型服务的账单为准。默认的价格是故意偏高的占位，请改成你用的服务的价目表
（每一百万 token 多少钱，单位是 `[budget]` 的 `currency`）：

```toml
[budget]
daily_limit = 50.0   # 所有房间加起来每天最多花多少，0 表示不限
task_limit = 10.0    # 一个任务最多花多少，0 表示不限
currency = "CNY"

[prices]
default = { input = 10.0, cached_input = 10.0, output = 30.0 }      # 没有单独写的模型
"deepseek-flash" = { input = 1.0, cached_input = 0.1, output = 2.0 }  # 名字和 [tiers] 里的 model 一样
```

| 情况 | 会怎样 |
|------|--------|
| 今天花到每日上限的 80% | 提醒一次 |
| 今天花到每日上限 | 之后的模型调用在发出去之前就被拦下：对话里的回复显示失败和原因，排队的任务不开工，正在做的任务停成「卡住了」。第二天（本机时间零点）起可以照常调用，排队的任务自动开工，停成「卡住了」的要你点继续；也可以调高 `daily_limit` 后重启 |
| 一个任务花到任务上限 | 任务停成「卡住了」等你。让它继续就是再给它一份额度 |

检查在每次调用之前做，所以最后一次调用可能让花费略微超过上限。回复写到一半被停下、模型没来得及报用量时，按字数估一个数记上。老的配置文件里没有 `task_limit` 和 `[prices]` 也能用：
任务上限按 10，价格按上面 `default` 那一行算。

`sa serve` 运行时，看门狗每分钟看一遍：

| 看到什么 | 做什么 |
|----------|--------|
| 一次运行跑了 1 小时 | 提醒；跑到 3 小时停下它，任务变成「卡住了」 |
| 正在做的任务 30 分钟没有输出、也没有调用工具 | 停下它，任务变成「卡住了」 |
| 人说完一句话之后，Bot 把同一句话说了 3 遍 | 停下这个房间里正在进行的对话 |
| 一个任务花的钱超过做完的任务平均花费的 3 倍（至少有 5 个做完的任务可比） | 停下它，等你决定要不要继续 |
| 排队的任务超过 50 个，或者有任务等了 10 分钟以上 | 提醒 |
| 最近一小时结束的运行里失败的超过三成（至少 3 次） | 提醒 |
| 数据目录所在的磁盘剩余不到 10%，或者数据库超过 1 GB | 提醒 |

看门狗不调用模型，也不往外发任何东西。被它停下的任务，改动都还在，让它继续就接着做。
提醒显示在时间线上方，可以收起；同一件事只提醒一次。

接口：`GET /api/usage`、`GET /api/notices`、`POST /api/notices/{id}/dismiss`。

### 定时任务

定时任务 = 一段存好的话 + 什么时候做。到点之后，负责的 Bot 在房间里做一轮，和你当面交代它一样能用工具、能开任务。
做完没有值得说的，它只回 `(pass)`，房间里什么都不留；说了话才会在时间线上出现「定时任务「…」到点了」和它的回复。

时间用五段式 cron 写（分 时 日 月 周），按本机时间：

| 写法 | 意思 |
|------|------|
| `0 9 * * *` | 每天 9:00 |
| `0 9 * * 1-5` | 工作日 9:00 |
| `*/30 * * * *` | 每 30 分钟 |
| `0 9,18 * * *` | 每天 9:00 和 18:00 |
| `0 9 1 * *` | 每月 1 日 9:00 |

每段可以写 `*`、数字、`a-b`、`a,b,c`、`*/n`、`a-b/n`；周里 0 和 7 都是周日。日和周都写了时，满足一个就算。

只有 `sa serve` 开着的时候才会到点去做，每 30 秒看一遍。几种不做的情况都记在定时任务上，界面和 `sa routine list` 里看得到：

| 情况 | 怎么处理 |
|------|----------|
| 到点时服务没开，晚了一个小时以上 | 这一次跳过，不补做，等下一次 |
| 今天的花费到上限了 | 跳过 |
| 负责的 Bot 被停用了，或者不在房间里了 | 跳过，不换别的 Bot 做 |
| 房间里正在对话 | 不插话，等它说完再做 |
| 连续 3 次没做成（模型报错、被停下、10 分钟没做完） | 自动停用并提醒你，处理好之后重新启用 |

同一个定时任务同一时刻只有一个进程在做：做之前先在数据库里占一个租约，15 分钟后过期；进程中途没了，过期之后才会有人接手。

接口：`GET /api/routines`、`POST /api/routines`、`PATCH /api/routines/{id}`、`DELETE /api/routines/{id}`、
`POST /api/routines/{id}/run`（现在就做一次）。

### 和外面连起来

两样都是可选的，没设对应的环境变量就不开。哪个仓库、哪个聊天进哪个房间，在界面右侧的「连接」页里定。

**GitHub 事件**

1. 设环境变量 `GITHUB_WEBHOOK_SECRET`（自己定一串随机的字符），再启动 `sa serve`。
2. 在「连接」页里填 `owner/name` 把仓库连到房间（或者 `sa link github <房间> <owner/name>`）。
3. 在仓库的 Settings → Webhooks 里新建一个：地址填 `你的公网地址/hooks/github`，Content type 选
   `application/json`，Secret 填第 1 步那一串，事件勾 Issues、Issue comments、Pull request reviews、
   Pull request review comments、Workflow runs。

`sa serve` 只听本机，GitHub 要能访问到它，得自己用反向代理或隧道把 `/hooks/github` 这一个地址放出去；别的地址不要放出去。

| 事件 | 怎么处理 |
| --- | --- |
| 新 issue、issue 和 PR 下的评论 | 进房间，交给入口 Bot（`[github] issue_labels` 写了标签就只收带这些标签的 issue） |
| PR 的评审、行内评论、CI 没通过或超时 | 只管任务开的 PR：进房间，交给那个任务的负责人 |
| CI 通过、被取消 | 只管任务开的 PR：摆在时间线上，不叫 Bot |
| 机器人账号做的、苦乐自己发的、没连房间的仓库、别的事件 | 不收 |

签名（`X-Hub-Signature-256`）不对的一律拒绝。GitHub 重试同一次投递（`X-GitHub-Delivery` 相同）不会变成第二条消息。
标题、正文、评论、文件名、分支名这些外人能随便写的东西：交给 Bot 时都围在 `<untrusted_external_content>` 里并说明只当资料看，里面的要求不照做；
Bot 觉得没有值得说的就只回 `(pass)`，房间里不留它的话。Bot 要动手还是照常走审批。

**Telegram**

1. 找 [@BotFather](https://t.me/BotFather) 建一个机器人，把它给的令牌放进环境变量 `TELEGRAM_BOT_TOKEN`，再启动 `sa serve`。
2. 在「连接」页里点「生成配对码」，在 Telegram 里把 `/pair 配对码` 发给机器人。码只能用一次，十分钟内有效。
   要连群，先把机器人拉进群，再在群里发 `/pair@机器人 配对码`（要带上机器人的名字，否则它收不到）。

连上之后：私聊里说的话都进房间；群里只有 `@机器人` 的和回复机器人的才进，别人之间聊天它不掺和。
Telegram 的机器人在群里默认开着隐私模式：只收得到带它名字的命令和对它的话的回复，**收不到 `@它` 的普通消息**。
想在群里直接 `@机器人` 说话，要在 @BotFather 里用 `/setprivacy` 关掉隐私模式（关掉之后把机器人请出群再拉进来），或者把它设成群管理员。
进来的话和你在界面里说的一样，可以 `@名字` 点名哪个 Bot。Bot 的回复送回那个聊天；
定时任务和 GitHub 事件引出的话，送到房间连着的每个 Telegram 聊天。你在界面里说的话引出的回复不往 Telegram 送。
只收发文字；审批卡仍然只能在界面里点。连着这个聊天的人都能让房间里的 Bot 做事，所以配对码不要给别人。

没送出去的话记在数据库里，网络不通或者被限速时过一会儿再送，最多试 8 次；放了一小时以上的不再送。

接口：`GET /api/links`、`POST /api/links`（连仓库）、`DELETE /api/links/{id}`、`POST /api/rooms/{id}/pairing`（生成配对码）、
`POST /hooks/github`（不用访问令牌，靠签名）。

### 技能

技能是事先写好的做事套路。放在数据目录的 `skills/` 里：`<名字>/SKILL.md`（旁边可以带别的文件），或者单独一个 `<名字>.md`。

```markdown
---
name: 发版
description: 发新版本之前要做的检查
bots: Coder, 助手
---
1. 跑测试
2. 改版本号
```

- 开头两行 `---` 之间的三项都可以不写：名字默认是文件名，说明默认是正文第一行，`bots` 不写就是所有 Bot 都能用。
- Bot 的提示词里只有「名字 + 一句话说明」；它觉得对得上了，用 `skill` 工具读全文（不用你批准），技能带着的别的文件也用它读。
- 每一轮对话都从磁盘上重新读：加、改、删技能不用重启。在对话里和任务里都能用。
- 最多 50 个技能，一个文件最多 64 KB。没认出来的文件和原因在界面右侧「扩展」页、`sa skill list` 和 `sa doctor` 里看。
- 自定义了 `prompts/chat.md` 的话，可以用 `{skills}` 指定这一段放在哪；没写就接在最后。

### 命令拿不到密钥

Bot 执行的命令不会继承 `config.toml` 里点了名的那几个环境变量：每个模型服务的 `api_key_env`、`[github]` 的 `token_env` 和
`webhook_secret_env`、`[telegram]` 的 `token_env`。命令的输出会回到模型手里，所以这些只留给 `sa` 自己用。
别的环境变量照常传给命令；要对命令保密的东西，不要放在 `sa` 的环境里。

### 外部 MCP 服务

在 `config.toml` 里每个服务写一节，重新启动之后它的工具会加给每个 Bot，名字是 `mcp__<服务名>__<工具名>`：

```toml
[mcp.files]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "."]
env = { LOG_LEVEL = "warn" }          # 给它的环境变量
env_from = ["FILES_TOKEN"]            # 把 sa 自己环境里的这几个变量原样传过去
auto_approve = ["read_file"]          # 这些工具不用问；别的每次调用都要你批准
```

- 只支持在本机启动、通过标准输入输出说话的服务；通过网址连接的远程服务还不支持。只用它的工具，资源和提示词模板不管。
- 服务在工作目录里启动，拿不到 `sa` 的环境变量（模型密钥、GitHub 令牌……），只有 `PATH`、`HOME` 这几个基本的，要给的在配置里写明。
- `sa serve` 启动时在后台连，连上了工具才出现；哪个没连上只在「扩展」页里写明原因，不耽误别的。服务中途退出了，下一次调用时重新启动一次。
- 一次调用最多等 120 秒；「停止」会通知服务取消。服务不在路径围栏里：它能做什么由它自己决定，所以默认每次都问你。
- `sa mcp test` 连一下试试、列出工具；`sa mcp list` 看配置了哪些。

接口：`GET /api/extensions`（技能和 MCP 服务现在的样子）。

### 重启之后

`sa serve` 不管是正常停下（Ctrl+C、`kill`）还是突然没了（断电、被强行杀掉），再启动时：

- 房间里的消息一条不丢，也不会多出重复的。
- 你说了、还没有 Bot 接的话，启动后接着回应。
- 写到一半的回复标成「中断」，**不会自己重做**：它可能已经执行过命令、改过文件，重做一遍会做两次。想让它接着做，再说一句就行。
- 等着你批准的操作按没批准算；没做完的任务重新排队接着做。
- 会话记录最后一行写了一半的丢掉，开了头没有结果的工具调用补上「结果丢了」，Bot 下一轮知道那一步没做成。

### 审计日志

要留底的事都记在审计日志里，只追加、不能改：

| 记什么 | 动作名 |
|------|------|
| 审批：允许一次、总是允许、这个任务里的命令都允许、拒绝、到时间没人处理、没等到答复就停下了 | `approval.*` |
| Bot 动手：执行命令、写文件、改文件、推送、开 PR、调用 MCP 工具、开任务、找别的 Bot | `tool.*` |
| 任务：开任务、继续、每次运行的开始和结束（连同没做成的原因）、换状态（做完、卡住、取消……） | `task.*` |
| 你改的设置：Bot、房间和成员、导入模板、撤销「总是允许」、连接、配对码、定时任务 | `bot.*` `room.*` `team.imported` `rule.*` `link.*` `pairing.*` `routine.*` |
| 程序自己做的：看门狗和预算守卫的提醒、定时任务自动停用、启动、停下、启动时的恢复 | `notice.*` `routine.disabled` `server.*` `recovery.done` |

每条有时间、是谁（你、哪个 Bot、程序、外面）、一句话说明、所在的房间和任务，命令原文这类细节点开看。
读文件、搜索这些不留痕迹的不记；普通对话在时间线上，也不记在这里。模型密钥、令牌、配对码不会写进去。记录留 180 天，更早的在启动时清掉。

- 界面：面板的「审计」页，可以只看这个房间、只看任务页里展开的那个任务，或者所有房间；再按审批、Bot 动手、任务、提醒筛。
- 命令行：`sa audit [--room 房间] [--task 任务] [--action 动作名开头] [--limit 条数] [--json]`。
- 接口：`GET /api/audit?room=&task=&action=&before=&limit=`，新的在前，`before` 用上一页最后一条的 `id` 翻页。

一件事没做成，先在任务页看它的运行记录，再到审计页只看这个任务：能看到它执行过哪些命令、哪一步等过批准、是谁停下的。
有「启动了」（`server.started`）而前面没有「停下了」（`server.stopped`），就是那一次没有正常退出。

### 对话太长怎么办

对话快占满模型的上下文窗口时，Bot 会先把前面的部分总结成一份摘要（时间线上显示「对话太长，压缩前面的内容」），
之后带着摘要和最近几条原文接着聊。房间里的消息和 `sessions/*.jsonl` 里的记录一条都不会删。

窗口大小默认按 1,000,000 token 算。模型的窗口更小、或者想早点压缩，在 `config.toml` 的档位里写
`context_window`，例如 `mid = { provider = "deepseek", model = "deepseek-flash", context_window = 128000 }`。
压缩线 = 窗口 − min(最大输出, 20,000) − 13,000。

| `sa mcp list` / `test [服务名]` | 外部 MCP 服务：看配置了哪些、连一下试试并列出工具 |
| `sa usage` | 今天和最近 7 天花了多少，按模型、Bot、任务分 |
| `sa audit [--room 房间] [--task 任务] [--action 动作名开头] [--limit 条数] [--json]` | 审计日志：谁在什么时候批准了什么、执行了什么、改了什么 |
| `sa doctor` | 体检 |

所有命令都可以加 `--data-dir <目录>` 指定数据目录。`sa serve`、`sa chat`、`sa task`、`sa routine`、`sa link`、`sa usage`、`sa audit`、`sa bot`、`sa room` 用同一份数据，同一个数据目录同一时刻只能有一个在运行；
`sa serve` 开着的时候，Bot 和房间在界面的「成员」面板里管理，定时任务在「定时」面板里管理。

`sa skill`、`sa mcp`、`sa doctor` 不占数据目录，服务开着也能用。

数据目录里：`config.toml` 配置，`skills/` 技能，`state.db` 房间和消息，`sessions/*.jsonl` 每个会话发给模型的完整记录，`spill/` 被截短的工具结果的完整内容，`work/` 任务的独立目录，
`prompts/chat.md`（可选）替换内置的系统提示词。里面可以用 `{bot_name}`、`{workspace}`、`{persona}`（这个 Bot 的分工）、`{team}`（房间里别的 Bot 和协作规则）；
没写后两个时，它们会接在提示词最后。

## 桌面版

`desktop/` 是一个 Tauri 外壳：一个窗口，里面起的是和 `sa serve` 同一个本机服务、同一个界面，数据目录和配置也是同一份。
它不是另一套程序，所以和 `sa serve`、`sa chat` 不能同时开着（同一个数据目录只能有一个在用）。

```sh
pnpm --dir web build                                  # 界面先构建好
cd desktop
cargo run -- --mock                                   # 直接运行
pnpm dlx @tauri-apps/cli@2.12.4 build --bundles nsis  # 出安装包：Windows 用 nsis，Linux 用 deb
```

- 第一次启动让你选 Bot 能读写的工作目录，之后记着；菜单「文件 → 更换工作目录」可以改（会重新启动）。
- 窗口里只显示苦乐自己的页面，PR 之类的外部链接交给系统的浏览器；导出的 Bot 模板存进「下载」文件夹。
- 关掉窗口就停下服务，正在写的回复会标成「中断」，和 `Ctrl+C` 停 `sa serve` 一样。
- 模型密钥、GitHub 令牌仍然从环境变量读。从开始菜单或桌面图标启动时读的是系统里的用户环境变量，不是某个终端里临时 `set` 的。
- 页面没有被授予任何桌面能力，它能做的事和在浏览器里一样多。
- 它是单独的一个 Cargo workspace，`cargo test --workspace` 不会编它；Linux 上编它要先装 WebKitGTK 等系统库（见 `.github/workflows/desktop.yml`）。
- Windows 上安装后叫「苦乐」；Linux 的包名只能用字母，叫 `kule`，在应用菜单里显示的仍然是「苦乐」。
- 安装包由 GitHub Actions 的 `Desktop` 工作流构建（手动触发，或者打 `v` 开头的标签），在运行记录的 Artifacts 里下载。安装包没有代码签名，Windows 第一次运行会有 SmartScreen 提示。
