# 安装

在一台新机器上从零到能用，照着做大约十分钟（不算下载和编译的时间）。

## 1. 准备

- Rust：版本写在仓库根目录的 `rust-toolchain.toml` 里，装了 `rustup` 的话第一次编译时会自动装对应的版本。
- Node 24 和 pnpm：只在编译前端时用。
- git：任务要用它开独立的工作目录；没有也能跑，任务会改成复制一份目录。

Windows、macOS、Linux 都可以。Windows 上 Bot 执行命令用的是 PowerShell。

## 2. 编译

```sh
git clone https://github.com/liziji555/myriad
cd myriad
pnpm --dir web install
pnpm --dir web build          # 先构建前端，它会被编进可执行文件
cargo build --release -p sa-cli
```

得到的可执行文件是 `target/release/sa`（Windows 上是 `sa.exe`），可以拷到别处单独用。

## 3. 体检

```sh
sa doctor
```

它逐项检查数据目录、配置、模型密钥、花费上限、git、GitHub 令牌、技能、MCP 服务、数据库、端口和前端页面，哪一项有问题会写明原因。数据目录和默认的 `config.toml` 在第一次运行 `sa serve` 时建好。

## 4. 先用假模型走一遍

```sh
sa serve --mock --workdir <你的项目目录>
```

终端会打印一个带令牌的链接，用浏览器打开。`--mock` 是不联网的假模型，不要密钥，回复按固定规则生成；能发什么样的消息见 README 的「运行」一节。

服务只监听 `127.0.0.1`，别的机器直接连不上；要从别的机器用，见第 7 节。

## 5. 接上真实模型

在数据目录的 `config.toml` 里写上模型服务和三个档位用的模型，把密钥放进环境变量，然后去掉 `--mock` 启动。完整的写法见 README 的「接上真实模型」。

接之前把 `[prices]` 改成你用的模型的价目表：每日花费上限是按它估算的，默认值偏高，会比实际更早到上限。

## 6. 把团队搬过来

在原来的机器上：

```sh
sa bot export --room <房间> -o team.toml
```

在新机器上：

```sh
sa bot import team.toml --update
```

新的数据目录里自带一个叫「助手」的 Bot。`--update` 的意思是：已经有同名的 Bot 时照模板改它，这样原来那个写好了分工的「助手」才搬得过来；不加的话同名的一律不动。

模板里只有 Bot 的名字、档位、分工和房间的成员，没有密钥、聊天记录和任务。技能要另外把数据目录里的 `skills/` 拷过来。

## 7. 放在服务器上跑（可选）

想关掉电脑任务也不断，就把 Myriad 装在自己的云服务器或 VPS 上（Linux），让它常驻：

```sh
sa service install --workdir <服务器上的项目目录>   # 加 --mock 先用假模型试
```

它装一个 systemd 用户服务：开机自己起来，崩了 5 秒后拉起，退出 SSH 登录也不停。模型密钥这类环境变量写进数据目录里的 `env` 文件（每行 `名字=值`），改完运行 `systemctl --user restart superagent`。不要了就 `sa service uninstall`，数据目录不动。

服务照旧只监听服务器的 `127.0.0.1`，不对公网开端口，从你的电脑通过 SSH 连过去：

```sh
sa connect ubuntu@1.2.3.4 --open   # SSH 端口不是 22 就加 -p 端口
```

它用系统自带的 `ssh` 开一条隧道，从服务器上的 `sa url` 拿到令牌，打印一个本机链接，`--open` 顺手用浏览器打开；隧道断了自己重连，`Ctrl+C` 断开（服务器上的服务照跑）。要求：

- 能用 SSH 密钥登录，不输密码。还没配密钥的话，第一次加 `--install-key`：在终端里输一次服务器密码，它把这台电脑的公钥（`~/.ssh/id_ed25519.pub` 这类，没有就新建一个）加进服务器的 `~/.ssh/authorized_keys`，之后都用密钥。密码不会保存。
- 服务器上的 `sa` 在 `PATH` 里，或者放在 `~/.local/bin`、`~/.cargo/bin`。

不装 `sa` 的电脑也能连：`ssh -N -L 4517:127.0.0.1:4517 ubuntu@1.2.3.4`，再打开服务器上 `sa url` 打印的链接。

桌面版启动时可以选「服务器」，填 `ubuntu@1.2.3.4`，做的事和 `sa connect` 一样，下次直接连。服务器不认这台电脑的密钥时，启动页里会出一个密码框，填一次就把公钥装上。

### 让服务器上的 Bot 用你电脑上的目录

服务器上的房间默认用服务器上的工作目录。想让 Bot 看、搜、改你电脑上的文件，在你的电脑上运行：

```sh
sa share D:\项目 --server ubuntu@1.2.3.4            # 名字默认是目录名，--name 另起
sa share D:\项目 --server ubuntu@1.2.3.4 --read-only # 只能看和搜，不能改
sa share D:\项目 --server ubuntu@1.2.3.4 --commands  # 还能执行编译、测试这类命令
```

然后在网页「成员」面板的「工作目录」里选这个共享目录。文件不上传，Bot 每次读、搜、改都经 SSH 隧道交给你电脑上的 `sa share` 去做，结果再传回去：

- 只开放这个目录，目录外的路径和指向外面的链接都会被拒绝；改文件照样要你批准。
- 你的电脑关了或断网时，要用这个目录的那一步会等着，`sa share` 重新连上后接着做。改文件时恰好断了的话，Bot 会先看一下文件再决定要不要重做。
- 同一个名字只能有一个 `sa share` 在跑，后开的会顶掉先开的。
- 加了 `--commands` 才能执行命令：命令在你电脑上的这个目录里跑（Windows 上用 PowerShell），每条都要在房间里批准，不能「以后都允许」。点停止会连同它启动的进程一起结束。断线时正在跑的命令接着跑，连回来后把结果交回去；`sa share` 本身被关掉的话，Bot 会先看一下结果再决定要不要重跑。命令和你在终端里跑的一样，碰得到这个目录之外的东西，批准前看清楚。
- 加了 `--commands` 的话，房间里的 harness 成员（Claude Code、Codex 这些）也在你电脑上跑：用的是你电脑上装的程序和登录的账号，每次启动都要批准。它在你电脑上的独立目录里干活（git 仓库开 worktree 和分支，不是的话复制一份，放在这台电脑的 Myriad 数据目录里），改动在成员面板里点「带回」才回到共享目录，点「丢弃」就删掉。点停止会结束它和它开出来的进程；那台电脑没连着时不能带回，丢弃的话服务那边不再记着它，你电脑上的独立目录留着。
- 用共享目录的房间里还不能开任务。

已经自己开好隧道的话，也可以用 `--url` 直接接服务器上 `sa url` 打印的链接（只能是本机地址）。链接里有令牌，放在环境变量 `SA_SHARE_URL` 里就不会出现在进程列表里。

## 桌面版（可选）

不想开终端和浏览器的话，可以用桌面版：一个窗口，里面是同一个服务和同一个界面，数据和配置与 `sa` 共用。

- **安装包**：仓库的 GitHub Actions 里 `Desktop` 工作流的运行记录，Artifacts 里有 Windows 的安装程序和 Linux 的 `.deb`。没有代码签名，Windows 第一次运行会有 SmartScreen 提示。
- **自己编**：`pnpm --dir web build` 之后，在 `desktop/` 里 `cargo run`，或者 `pnpm dlx @tauri-apps/cli@2.12.4 build` 出安装包。

打开就是本机，工作目录默认是「文稿」下的「Myriad」文件夹，点左栏底下的连接按钮可以换文件夹或连服务器。模型密钥要设成系统里的用户环境变量（Windows：设置里搜「环境变量」，或者 `setx DEEPSEEK_API_KEY 你的密钥` 之后重新打开）。
桌面版开着的时候，`sa serve`、`sa chat`、`sa usage` 这些要用同一个数据目录的命令会提示目录正在被使用；先关掉桌面版再用。

## 出了问题

- 页面打不开：要用终端里打印的那个带令牌的链接打开；只输入地址不带令牌会被拒绝。
- `sa bot`、`sa room` 报数据目录被占用：`sa serve` 开着的时候它们不能用，在界面的「成员」页里管理。
- 想知道某件事是谁在什么时候做的：`sa audit`。
