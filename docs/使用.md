# 使用

一页纸的上手说明。每一项的细节在 README 对应的小节里。

## 房间和 Bot

- 左栏是房间，中间是对话，右栏是这个房间的任务、成员、用量这些。
- 一个房间里最多 6 个 Bot，各写各的分工。`@名字` 点名谁就谁答；不点名时按分工挑一个，挑不出来交给入口 Bot。
- 在右栏「成员」页新建、修改 Bot，把 Bot 拉进或请出房间，换入口。同一页最下面可以把这个房间的团队导出成模板文件，或者导入一份模板。

## 对话

- 回车发送，Shift+回车换行。输入 `@` 点名一个 Bot，输入 `/` 找命令（打开某个面板、新建房间、停止回复）。
- 写了一半没发的话按房间记着，换房间、刷新都还在。
- Bot 回复下面的「N 步操作」点开能看到它每一步做了什么、拿到了什么结果。
- 「停止」会停下正在写的回复，连同它启动的命令。

## 审批

- 工作目录里面写文件直接做。执行命令、往工作目录外面写、推送分支、开 PR、调用 MCP 工具会先弹审批卡：允许一次、总是允许、拒绝。
- 10 分钟不处理按拒绝算。
- 没有系统级的沙箱：命令一旦批准，就以你的身份运行。

## 任务

- 要花些功夫的事，Bot 会开成任务，在独立的目录里做，做完交结果等你验收。验收通过，改动才回到你的工作目录。
- 右栏「任务」页里可以回答它的问题、打回重做、停止、取消。

## 花了多少、谁做了什么

- 右栏「用量」页：今天和最近 7 天，按模型、Bot、任务分。到每日上限后模型调用会被拦下。
- 右栏「审计」页：每一次审批、Bot 执行的命令和改的文件、任务的每一步、设置的改动。命令行里是 `sa audit`。

## 定时、外面的连接、技能

- 「定时」页：到点让一个 Bot 做一件事，没话说时它不出声。只有 `sa serve` 开着才会做。
- 「连接」页：把 GitHub 仓库的事件、Telegram 聊天接进房间。
- 「扩展」页：数据目录 `skills/` 里的技能和 `config.toml` 里配的 MCP 服务。

## 键盘

- `Ctrl K`（Mac 上 `⌘ K`）：命令面板，搜房间、Bot、任务和动作。
- 房间名左边的「‹ 房间」收起左栏；右栏左边那条线可以拖宽，也可以聚焦后用左右方向键调。

怎么检验这套东西合不合用，见《[用六个信号检验](验收.md)》；界面逐条的情况见《[界面验收 20 条](界面验收.md)》。
